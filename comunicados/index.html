Basic Authentication deixa de ser suportada em integrações de entrada

Prazo: agir até novembro de 2027 (release Denmark)

A partir da Denmark, usuário e senha em requisições de API de entrada (REST, SOAP e outras) deixam de ter suporte. A recomendação é migrar para OAuth 2.0, mTLS ou token federado.

O que muda

  • A partir da release Denmark, planejada para novembro de 2027, a ServiceNow encerra o suporte a Basic Authentication para integrações de entrada: credenciais de usuário e senha enviadas em requisições de API de entrada (REST, SOAP e outras interfaces).
  • Pode continuar funcionando na instância, inclusive depois de upgrades, mas sem suporte: a ServiceNow não vai atender problemas ligados a ela.
  • Nas releases antes e depois da Denmark podem entrar controles adicionais sobre o uso, incluindo mudanças na configuração padrão de novas integrações. A ServiceNow diz que vai avisar antes.

O que fazer

  • Migrar as integrações para um método suportado: OAuth 2.0, mutual TLS (mTLS) ou autenticação federada por token.
  • Usar o KB3220405 para identificar quais integrações da instância usam Basic Authentication e como migrar, inclusive recursos da plataforma que dependem dela.
  • Se nenhuma integração usa Basic Authentication, não é preciso fazer nada.

Bom saber

  • É separado e mais amplo que a atualização de segurança de junho de 2026 (KB3025707), que restringiu Basic Authentication para contas de login interativo. Este vale para todas as integrações de entrada, inclusive contas de serviço (Web Service Access Only).
  • Converter a conta para Machine identity (antigo Web Service Access) continua valendo como passo de curto prazo, mas não substitui a migração.
  • Motivo citado pela ServiceNow: Basic Authentication envia usuário e senha em toda requisição e não aceita MFA, por isso é o alvo mais comum de ataques automatizados de abuso de credenciais.
  • Dúvidas técnicas: abrir case no suporte da ServiceNow ou falar com o representante ou parceiro.

Referências

  • KB3220405: identificar e migrar integrações com Basic Authentication (exige login no Now Support)
  • KB3025707: atualização de segurança de junho de 2026 (exige login no Now Support)

getRefRecord() entre escopos ganha checagem de segurança na Brazil

Prazo: release Brazil (novembro de 2026)

Uma nova propriedade controla a checagem de escopo quando getRefRecord() é usado entre aplicações: ligada por padrão em instâncias novas na Brazil e desligada em instâncias que fizerem upgrade.

O que muda

  • Nova glide property glide.script.enforce_scope_checks_on_get_ref_record, que controla a checagem quando a API JavaScript getRefRecord() é usada entre escopos de aplicação.
  • Instâncias novas na Brazil: a checagem já vem ativada.
  • Instâncias que fizerem upgrade para a Brazil: o padrão é false; você ativa quando estiver pronto.
  • Amplia a proteção de fronteira de escopo que a release Australia trouxe para dot-walking entre escopos por campos de referência (KB2793170).

O que fazer

  • Ler o KB3142985 para entender como a checagem funciona e para avaliar e corrigir os usos de getRefRecord() entre escopos antes de ativar.
  • Dúvidas técnicas: abrir case no Now Support com o assunto Cross-Scope Access Security Enhancement (Glide Element API: getRefRecord()).

Referências

  • KB3142985: como funciona e como corrigir o acesso entre escopos (exige login no Now Support)
  • KB2793170: proteção de dot-walking entre escopos (Australia) (exige login no Now Support)
